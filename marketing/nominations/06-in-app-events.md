# App Store In-App Events (a Direct Featuring Lever)

App Store **In-App Events** are timed events that appear *on your product page and
across the App Store*, and **editors can feature them directly**. Creating one
around your update turns a passive nomination into something editors can actually
surface. They're one of the highest-leverage, lowest-cost things you can do here.

**Where:** App Store Connect → your app → **In-App Events** → *Create*.
**Lead time:** submit the event for review well before its start (allow ~1–2 weeks);
it can be featured up to ~2 weeks before it begins.

---

## Event 1 — "Rags to Riches Week" (recommended launch event)

- **Event type:** Challenge.
- **Name (≤30 chars):** `Rags to Riches Week`
- **Short description (≤50 chars):** `Start broke. Build a fortune in one year.`
- **Long description:**
  ```
  Start with nothing and race to a net-worth target before the in-game year ends.
  Loans, the market, real estate — every decision compounds. How far can you get?
  ```
- **Badge:** Challenge.
- **Timing:** align START with the update's release; run ~1 week.
- **Deep link:** open directly into a fresh life / the challenge scenario.
- **Why it fits:** it dramatizes the core loop (start broke → compound wealth) in a
  single, shareable frame — exactly the app's editorial hook.

> Implementation note: an In-App Event needs *something* in-app for the deep link to
> land on. If a dedicated challenge mode doesn't exist yet, point it at a fresh-start
> life with the existing net-worth milestone/achievement as the goal. Keep the event
> honest — it must reflect real in-app content.

## Event 2 — "New Life, New You" (seasonal / evergreen)

- **Event type:** Special Event / New Season.
- **Name:** `New Life, New You`
- **Short description:** `A fresh start — pick a path, change your fate.`
- **Timing:** New Year, back-to-school, or any fresh-start editorial moment.
- **Why it fits:** maps the "start with nothing, build everything" premise onto the
  calendar moments editors curate around.

---

## Assets each event needs

- **Event card image / video** (short loop) — reuse the app-preview beats from doc 05.
- **Localized** name + descriptions for at least the top markets (en, es, pt-BR, de,
  fr, ja, ko, zh-Hans).
- A working **deep link** into the relevant in-app content.

## Checklist

- [ ] Event created and submitted for review ≥ 1–2 weeks before start.
- [ ] Deep link tested on-device (lands on real, matching content).
- [ ] Localized for top markets.
- [ ] Start date aligned with the featured update + the featuring request in doc 01.
- [ ] Referenced in the featuring nomination (doc 01, field 8).
- [ ] Content claims are honest — the event reflects actual in-app content.
