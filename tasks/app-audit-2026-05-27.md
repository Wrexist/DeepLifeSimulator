## TIER 0 — Ship-blocking. Fix before any release build.

### 0.1 DevToolsModal is enabled in production
- `components/SettingsModal.tsx:50-52, 635-636`, `components/DevToolsModal.tsx:23-100`
- Author left a `// TEMP: leave enabled in production for now` comment. Modal exposes God Mode (`preventDrain` restores all stats to 100 weekly), arbitrary money/gems TextInput, and full `restartGame`. Trivializes every IAP and progression curve.
- **Fix:** wrap the entry and the JSX in `if (__DEV__)`.

### 0.2 STATE_VERSION drift causes silent save corruption every load
- `contexts/game/GameActionsContext.tsx:315, 4284` — save writes `version: initialState.version || 1` from the **provider's injected** initialState rather than the imported constant. If that ever resolves to undefined/0, every save stamps `version: 1`, and on next load `runMigrations()` runs all 17 migrations against an already-v18 state. Migrations are not idempotent (darkWeb.heat re-seeds from wantedLevel; loan.originalAPR mutates).
- CLAUDE.md says `STATE_VERSION = 10`; the code is actually `STATE_VERSION = 18` (`contexts/game/initialState.ts:6`). Update the doc.
- **Fix:** import `STATE_VERSION` from `@/contexts/game/initialState` and use it directly when stamping saves.

### 0.3 Failed migrations still bump version → permanent silent data loss
- `utils/saveMigrations.ts:515-531`
- Outer loop unconditionally sets `state.version = targetVersion` even when the migration function throws. After a failure on v15, the version is bumped to v16, v17, v18 and the failed migration is **never re-attempted** on future loads.
- **Fix:** bump `state.version` only inside the successful branch.

### 0.4 IAP grants applied twice (in-memory + disk)
- `services/IAPService.ts:1336-1355` — `applyBenefit()` calls `stateUpdater(productId)` (in-memory + setTimeout(100ms) `saveGame(true)`), then **immediately** calls `applyBenefitToDisk(...)` which reads the disk image and re-applies the same gems/money/youthPills/perks. The 100ms race window lets disk be read pre-save, so the grant is added on top of the pre-grant state. Next cold launch reloads doubled.
- **Fix:** check `processedIAPTransactions` once, apply once via the in-memory path, drop the disk-side double-apply.

### 0.5 YouthPill IAP is a no-op (paid product does nothing)
- `components/YouthPillModal.tsx:20-34`
- Writes to `userProfile.age` but death checks `gameState.date.age`. Player burns Youth Pill (real-money purchase), age unchanged, can keep buying more, all consumed for nothing. Refund liability + App Store fraud surface.
- **Fix:** update `date.age` (and optionally `weeksLived`).

### 0.6 Revive creates a death-revive whale loop
- `contexts/game/GameStateContext.tsx:108-133` + IAP Revival Pack path in `IAPService.ts:995-1005`
- After old-age death (≥80), revive charges 15,000 gems, resets health/happiness/energy, clears the death popup — but doesn't roll back `weeksLived` or `date.age`. Next weekly tick re-rolls death immediately. Whale burns unlimited gems with no progress.
- **Fix:** clamp `date.age` to `deathAgeThreshold - 1` on revive, or refuse revive past threshold.

### 0.7 LoanManager creates loans with no banking-account link (free money)
- `components/LoanManager.tsx:168-230`
- This UI path builds a `newLoan` literal and prepends to `gameState.loans` **without going through `LoanActions.acceptLoan`**. Proper path stamps a `depositAccountId` so `payLoanWeekly` can debit; UI-created loans lack that field, so weekly autopay **never debits them**. Principal is deposited as cash, balance never decreases.
- Also `repayLoan` (LoanManager.tsx:232-275) has a discount/cash-check mismatch: `cash < finalAmount` passes when `cash < remaining`, fully clearing the loan with under-payment.
- **Fix:** delete this entry-point and route all loan creation through `contexts/game/actions/LoanActions.ts`.

### 0.8 12 components bypass iOS 26 TurboModule fallbacks
- Direct `import { LinearGradient } from 'expo-linear-gradient'`:
  - [components/EnhancedAchievementScreen.tsx:13](components/EnhancedAchievementScreen.tsx#L13)
  - [components/EnhancedAchievementCard.tsx:9](components/EnhancedAchievementCard.tsx#L9)

  - [components/QuickActionsPanel.tsx:3](components/QuickActionsPanel.tsx#L3)
  - [components/TutorialOverlay.tsx:3](components/TutorialOverlay.tsx#L3)
  - [components/TutorialTooltip.tsx:3](components/TutorialTooltip.tsx#L3)
  - [components/TutorialTrigger.tsx:3](components/TutorialTrigger.tsx#L3)
  - [components/ui/ErrorBoundary.tsx:3](components/ui/ErrorBoundary.tsx#L3) — **critical**, the global error boundary itself
  - [components/ui/EnhancedButton.tsx:10](components/ui/EnhancedButton.tsx#L10)
  - [components/ui/AnimatedButton.tsx:10](components/ui/AnimatedButton.tsx#L10)

### 0.9 `app.config.js` missing config plugins for installed native packages (Hard Rule #4)
- [app.config.js:64-97](app.config.js#L64-L97) vs [package.json](package.json)
- Missing plugins for `expo-tracking-transparency`, `expo-in-app-purchases`, `expo-updates`, `expo-dev-client`. The first one already hand-rolls Info.plist but no plugin entry → autolinking gap.
- **Fix:** add `["expo-tracking-transparency", { userTrackingPermission: "..." }]` and audit the rest.

### 0.10 `global.RCTFatal = () => {}` suppresses every native fatal silently
- [app/_layout.tsx:333](app/_layout.tsx#L333)
- Eats unrecoverable native exceptions (OOM, JS heap blown, native null deref). The app continues running with a corrupt bridge and crashes harder later with no diagnostic. Combined with the ExceptionsManager interception at lines 347/363/379, production crashes become invisible.
- **Fix:** Log + persist the fatal via `errorStorage`/`remoteLogger`, then re-throw on next frame.

### 0.11 HMAC bypass paths accept unsigned saves in production
- `utils/saveValidation.ts:198, 1086-1123`
- When `ALLOW_WEAK_SAVE_MIGRATION = true` and no key, `calculateHmacSignature` falls back to a CRC32 of the data — **trivially forgeable**, written next to the `hmac` field as if valid.
- `verifySaveData` accepts checksum-only saves when `!REQUIRE_SIGNED_SAVES || ALLOW_WEAK_SAVE_MIGRATION`. `requireSignedSaves` defaults true only when `NODE_ENV==='production' && env var !== 'false'`. If an operator forgets to set `EXPO_PUBLIC_REQUIRE_SIGNED_SAVES`, unsigned saves silently accepted.
- **Fix:** refuse writes when key missing; never synthesize a fake HMAC. Set `EXPO_PUBLIC_REQUIRE_SIGNED_SAVES=true` explicitly in `eas.json` production env.
