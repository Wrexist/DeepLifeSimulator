**Date:** 2026-06-15 · **Baseline:** 2387 tests / 156 suites / 308 snapshots green · type-check 0 errors
**Method:** Six parallel source-verified audits (Release/monetization, Stability/save, Economy/exploits,
Performance/architecture/type-safety, UX/design/a11y, Product/content/testing) run against current `main`

---

## 0. Executive summary

**The app is code-ready for TestFlight / Play Store.** Every release blocker is **ops/config**, not
code. The economy is hardened (all known money-printers fixed + a live money-conservation stress test),
the save/migration layer is robust (validate→repair→migrate v10–v19, double-buffer, HMAC, quota, mutex,
backups), and the recent perf sprint made both the in-game UI and the pre-game menu feel instant.

The real forward work splits into three buckets:
1. **Ship it** — a short ops checklist (Section 1).
2. **Durability** — the single biggest engineering gap is **near-zero UI render-test coverage**, plus
   the `nextWeek` decomposition and a few stability tests (Sections 2–3).
3. **Growth** — there is **no live-ops capability** yet (content is hardcoded; no remote config /
   analytics / A/B). That's the "what's next" to sustain the game after launch (Section 5).

These gate a revenue-generating, store-compliant build. None require code changes — they require EAS
secrets, a backend endpoint, and policy/CI hygiene.

yet — all of the below are greenfield.

## 6. Recommended sequencing

**Phase A — Ship (days, ops-led):** L1–L6. Stand up IAP verify, set AdMob + HMAC EAS secrets, align
privacy policy, harden CI gate, rotate/purge the leaked key. → submittable, monetizing build.

**Phase B — Launch hardening (1–2 sprints):** H1 (UMP), H4+H5 (save stress + load-validate tests),
H2 (render-test suite — start it now, grow continuously), H6+H7 (consolidate IAP paths, verify income
mapping), M2 (memory-leak test). → confidence the live build won't soft-lock or mis-monetize.

**Phase C — Feel & polish (1–2 sprints):** H3 (nextWeek decomposition + instrumentation), M1 (selector
migration of remaining hot consumers), H8+H9 (a11y + BaseModal), M5+M6 (FirstWeek rewards + gem curve).

**Phase D — Operate as a live service (multi-sprint):** N1 (remote content) → N2 (analytics) → N4
(scorecard) → N3/N5/N6 (A/B, deterministic sims, seasonal events). M3/M4 (income ledger + gem idempotency)
land here as the economy-integrity backbone for live tuning.
