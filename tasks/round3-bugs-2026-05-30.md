# Round 3 — JIT bailout, onboarding UX, remaining cleanup

Round 1 fixed the structural crashes (render loops, native modules, save system). Round 2 cut the per-action memory growth, the death-modal soft-lock, and the worst economy exploits. Round 3 finishes the deferred items: the biggest perf win (JIT-bailout), the onboarding UX gaps, and the long tail of `safeSettings` derefs.

## Applied

### R3-A — JIT-bailout fix in `nextWeek`
[contexts/game/GameActionsContext.tsx](contexts/game/GameActionsContext.tsx) — hoisted **all 25 inline `require('@/lib/...')` calls** to ES imports at top of file. Removed the wrapping `try/catch` blocks whose only purpose was to silence missing-module errors that never occur in production (the modules all exist). Round 2's perf audit flagged this as the #1 remaining perf finding: those try/catch wrappers disabled Hermes/V8 JIT optimization for the entire ~1500-line `setGameState` updater, forcing it to run interpreted (5-10× slower).

To keep the change safe:
- The non-require try/catch blocks (e.g. consequence-progression merge, pulse/spark/hustle tick) were **kept** — they wrap real failure-tolerant operations, not the module load.
- Aligned `GameState.checkpoints[].snapshot` type from `string` to `Partial<GameState> | string` to match the canonical `Checkpoint` type that the ES import surfaced — the previous mismatch was hidden by `require()`.

### R3-B — Onboarding state persistence
[src/features/onboarding/OnboardingContext.tsx](src/features/onboarding/OnboardingContext.tsx) — rewrote to AsyncStorage-back the draft. State is hydrated on `OnboardingProvider` mount, debounce-persisted (500ms) on change, and cleared on completion via a `clearDraft()` callback wired into [app/(onboarding)/Perks.tsx](app/(onboarding)/Perks.tsx). 30-day TTL so stale drafts don't surprise returning players.

Closes the round-2 finding: a player typing "Bartholomew Featherstone", getting a phone call, and letting iOS reap the app no longer lands back at a blank Customize screen.

### R3-C — Android hardware back handlers
New hook [hooks/useHardwareBack.ts](hooks/useHardwareBack.ts) wraps `BackHandler.addEventListener('hardwareBackPress', ...)` with proper cleanup. Wired into all 4 onboarding screens ([Customize](app/(onboarding)/Customize.tsx), [Scenarios](app/(onboarding)/Scenarios.tsx), [Perks](app/(onboarding)/Perks.tsx), [SaveSlots](app/(onboarding)/SaveSlots.tsx)). Previously the project had zero `BackHandler` usage anywhere, so deep-linked players using the system back gesture got dumped on blank screens.

### R3-D — `safeSettings` sweep across 21 components
Bulk applied the round-2 `safeSettings(gameState)` pattern to every remaining component that did `const { settings } = gameState` raw: `TutorialOverlay`, `FinanceOverview`, `TravelModal`, `WeeklyEventModal`, `DailyRewardPopup`, `ActivityCommitmentModal`, `LegacyTimeline`, `WelcomeBackPopup`, `YouthPillModal`, `SkillTreeModal`, `SettingsModal`, `SeasonalIndicator`, `ProgressOverview`, `NetWorthDisplay`, `LoadingStates`, `settings/LifeGoalsPanel`, `GemShopModal`, `mobile/WeddingPlanningModal`, `LegacyOverviewTab`, `Journal`, `HelpModal`. With round 2's 12 components, every reported site is now defensive.

### R3-E — More memory caps
- `socialMedia.scandalHistory` capped at 30 at both PulseActions writers ([PulseActions.ts:519, 540](contexts/game/actions/PulseActions.ts))
- Per-company `hustleApp.companies[id].scandalHistory` capped at 25 in [hustleTick.ts:153](lib/business/hustleTick.ts)
- `banking.creditScore.inquiries` capped at 50 in [operations.ts:190](lib/banking/operations.ts) — credit-application spam in one week can no longer grow this unbounded

### R3-F — Subscription/IAP listener leaks + TextInput hygiene + AnimatedMoney churn
- [services/IAPSyncService.ts](services/IAPSyncService.ts) and [services/SubscriptionService.ts](services/SubscriptionService.ts) now capture the `iapService.addListener` unsubscribe callback and expose a `dispose()` method. Previously discarded the return → listeners leaked on every hot-reload.
- [components/ui/AnimatedMoney.tsx](components/ui/AnimatedMoney.tsx) tracks the in-flight `Animated.timing` via ref and stops it before starting the next one. Previously rapid money changes left orphaned animations racing the listener callback.
- TextInput hygiene: [components/banking/AmountInputModal.tsx](components/banking/AmountInputModal.tsx) and [components/LoanManager.tsx](components/LoanManager.tsx) money inputs now have `autoCorrect={false}`, `autoCapitalize="none"`, `spellCheck={false}`, `returnKeyType="done"` — fixes the Samsung-One-UI autocorrect-bar-eats-vertical-space issue.
