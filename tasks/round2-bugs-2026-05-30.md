# Round 2 — Audit Summary

Five parallel audits ran across game mechanics, memory leaks, UI/UX, performance hot paths, and hidden crash paths. ~126 findings total. The top items were applied and verified.

## Applied this pass

### R2-A — Universal `settings` / `stats` / `date` / `userProfile` guard pattern (the recurring crash)
Created `utils/safeGameState.ts` with `safeSettings`, `safeStats`, `safeDate`, `safeUserProfile`, `safeDarkMode` helpers that return canonical defaults when the field is undefined. Wired into the 12 components that previously deref'd these fields raw and would crash on a mid-migration/mid-DevTools render:
- `TombstonePopup`, `DeathPopup` (the death/soft-lock cluster)
- `DailySummaryModal` (fires every week tick)
- `LifeMomentModal`
- `MemoryBookModal`, `FamilyTab`, `FamilyTreeModal`, `AncestorProfileModal`
- `LeaderboardModal`
- `LoanManager`
- `CureSuccessModal`
- `AutoSaveIndicator` (globally mounted in the layout)

### R2-B — Memory caps at the mutation sites
- `eventLog` capped at 500 in [GameActionsContext.tsx](contexts/game/GameActionsContext.tsx) (previously grew to 100s of entries between saves, with every per-action `setGameState` copying the whole array)
- `dailySummary.events` capped at 50 in `MoneyActions.ts` + 2 sites in `ItemActionsContext.tsx`
- `lifeMilestones` capped at 200 in `DatingActions.ts` (3 sites) + `SocialActionsContext.tsx`
- `eventChains` capped at 50 in `GameActionsContext.tsx`
- `curedDiseases` deduped via Set + capped at 30 in `ItemActionsContext.tsx`

### R2-C — Checkpoint migration on rewind
[lib/timeMachine/checkpointSystem.ts](lib/timeMachine/checkpointSystem.ts) `rewindToCheckpoint` now runs the snapshot through `runMigrations` + `repairGameState` before restoring. Previously a checkpoint captured at STATE_VERSION 14 restored verbatim into v18 → every screen that read v15-v18 fields black-screened.

### R2-D — Production log level dropped from INFO to WARN
[utils/logger.ts](utils/logger.ts) — the `nextWeek` body had 16+ `logger.info(...)` calls (template-string allocation + `console.info` + remote-logger ring buffer push) firing every week-advance in production. Dropping prod to WARN turns those into a single early-exit in `shouldLog`.

### R2-E — IAPHandler replaced JSON round-trip with `structuredClone`
[components/IAPHandler.tsx](components/IAPHandler.tsx) — `JSON.parse(JSON.stringify(prevState))` was a 60-150ms hitch per IAP AND silently dropped `undefined`, `Date`, `Map`, `Set`, and function properties.

### R2-F — `validateGameState(state, true)` autoFix path skipped
Round 1's P0-10 made `repairGameState` deep-clone its input. That repair fires inside `validateGameState(state, true)` — so the 4 sites passing `true` (saveGame, nextWeek post-validate, conflict resolver, health-check interval) each triggered a 30-80ms structuredClone. Changed all 4 to `false`; repair still runs explicitly in the `if (!validation.valid)` branch.

### R2-G — Economy / mechanic exploits
1. **`batchUpdateMoney`** now rejects overdrafts (matching the round-1 P1-1 fix to `updateMoney`) — silent clamp-to-zero is gone.
2. **`buyStockMarket`** now includes the 2% fee in the affordability check — previously a player with exactly `notional` cash could buy and end up with negative money.
3. **`acquireNewIdentity`** preserves mortgage + auto loans (secured against existing assets). Previously 0.5 BTC wiped *all* loans including million-dollar mortgages.
4. **`enterHobbyTournament`** capped to 1 entry per hobby per week. Previously the deterministic roll was keyed only on (week, hobbyId), so a single win could be re-collected unlimited times that week.
5. **`ensureHustle`** in HustleActions now clones `lifetimeStats` so `ha.lifetimeStats.totalX += 1` writers don't mutate `prev` in place (StrictMode double-counts).
6. **Prestige `generationBonus`** operator-precedence bug fixed: was `(generationNumber || 1 - 1) * 50` (always evaluates to `generationNumber * 50`), now `Math.max(0, (generationNumber || 1) - 1) * 50`. First-generation players were getting +50 free points.
7. **`stakeCrypto`** validates amount is finite + positive and lockWeeks is an integer 1-4 — was vulnerable to NaN/Infinity stakes and fractional-week exploits.
8. **`executeMarket`** rejects non-finite amounts and amounts > 1e12 — was vulnerable to Infinity-poisoning the holdings' average-price.

### R2-H — UI / animation fixes
1. **WeeklyEventModal + LifeMomentModal** now render exclusively — previously both could be active on the same tick with stacked transparent backdrops blocking taps.
2. **LeaderboardModal** got the missing `transparent` prop, mojibake category icons (`µ`, `‚`) replaced with real emoji, animation loops captured and stopped on cleanup, and `userProfile` deref's optional-chained.
3. **TopStatsBar spinner** loop now captured and `.stop()`'d in the cleanup — previously every `isAdvancingWeek` toggle stacked another native-driver loop.
4. **ErrorBoundary** prunes old `error_backup_*` keys BEFORE writing the new one. Previously cleanup only fired on QuotaExceededError, so under normal conditions every crash wrote another 1-4MB blob forever.

## Intentionally deferred for follow-up

These are real findings but lower-impact or require larger refactors:

### Hidden crashes (P3-ish)
The recurring `const { settings } = gameState` pattern still appears in ~15 other components flagged by the audit (Journal, HelpModal, SkillTreeModal, SettingsModal, TutorialOverlay, SeasonalIndicator, GemShopModal, WelcomeBackPopup, YouthPillModal, TravelModal, DailyRewardPopup, ActivityCommitmentModal, LegacyTimeline, LegacyOverviewTab, FinanceOverview, NetWorthDisplay, ProgressOverview, LoadingStates, settings/LifeGoalsPanel, mobile/WeddingPlanningModal). These crash less often (rare-path components or already partially guarded) — sweep at leisure with the same `safeSettings(gameState)` pattern.

### Performance (the JIT-bailout)
The audit's #1 perf finding was the ~10 `try/catch` wrappers around `require()` inside the `nextWeek` `setGameState` updater — those disable JIT optimization for the entire 1500-line function. Removing them is a 2-5× speedup but requires hoisting requires to top-of-file ES imports AND verifying jest mocks still work. Worth a dedicated pass with the test suite as guardrail.

### UI / Onboarding
- Onboarding state lost on backgrounding (no AsyncStorage persistence) — needs a wrapper around the OnboardingContext state.
- Zero Android hardware-back-button handlers anywhere in the project — needs `BackHandler.addEventListener` in each onboarding screen.
- Money TextInputs missing `autoCorrect={false}` in 8+ places — straightforward but tedious.
- Image components missing `onError` fallbacks (Pulse / Spark / Tinder profile photos) — needs an `ImageWithFallback` helper component.
- Computer / mobile sub-apps have no accessibility props anywhere.

### Memory (lower-impact)
- `socialMedia.scandalHistory`, `brandInbox.history`, `darkWeb.recentEvents`, `darkWeb.laundering`, `politics.scandals`, `creditScore.inquiries`, `npc.memories` all flagged for unbounded growth. Save-time pruning caps a few of these but in-memory caps are still missing for most. Apply same `slice(-N)` pattern at writers.
- `IAPSyncService.setupIAPListeners` and `SubscriptionService.setupIAPListeners` discard their unsubscribe callbacks — listeners leak on hot-reload.
- `AnimatedMoney` re-installs an Animated listener on every value change without stopping the previous timing animation — listener churn on every money tick.

### Economy (rest)
~25 more findings from the economy audit: race conditions in mining-upgrade affordability, pet `feedPet` inventory going negative, wedding/propose double-charge, `payCreditCard` not improving credit score / annual fee not collected, disease worsening unbounded 10%/week compounding, `applyLoanPayment` not crediting principal vs. interest correctly, etc. Mostly anti-exploit hardening rather than crash fixes.

---

Round 1 fixed the structural crashes (render loops, native modules, save system). Round 2 hit the next layer down — the recurring crash pattern in 12 components, the memory leak that explained 30-min slowdowns, the perf cost of validation-on-every-save, the checkpoint-migration black-screen, and the worst economy exploits. A reasonable Round 3 would focus on the JIT-bailout perf win, the remaining unbounded arrays, and the onboarding/back-handler UX polish.
