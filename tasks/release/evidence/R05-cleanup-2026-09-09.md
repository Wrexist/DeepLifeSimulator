Date: 9 September 2026. Baseline: `b5aa2a8cdc8e6f0d5468a9cb8f86408fe63ab311`.
Implementation: `591f372345d0be784169da7a96ac69827945f4ce`.
Environment: Linux x64, Node v24.19.0, Jest/React test renderer; not native Hermes.

## Reproduction and disposition

The normal suite had passed while warning about worker teardown; a previous serial
diagnostic had not exited. This investigation split the suites by domain and used
a temporary Node async-hooks Jest environment to inspect referenced resources after
environment teardown. It did not cancel resources, unref them or force process exit.
The domain splits themselves exited successfully. Thus the earlier observation is
not evidence of an invariably infinite hang.

| Resource traced | Owning cause | Focused correction |
| --- | --- | --- |
| 500ms readiness deadlines across render/storage suites | `Promise.race` left its timeout alive when storage resolved or rejected | Clear the attempt's deadline in `finally`; keep timeout/retry/fallback semantics |
| 120s autosave and 600s health-check intervals in jail-action fixture | `root.unmount()` scheduled cleanup without waiting for React | Await `act` teardown in `afterEach`, including failed assertions; assert each interval is cleared |
| 90s purchase deadline in subscription-routing test | Started purchase promise was abandoned without any store event | Deliver cancellation via the adapter's actual listener, await its result and assert its deadline was cleared |

The storage regression failed before the fix with **1** and **2** live timers
instead of zero after successful and retrying reads. After correcting mock isolation,
the before run was 2 failed / 8 passed, not a failure of JSON parsing or fallback.
The added interval-cleanup assertions failed all four jail cases before awaiting
unmount. All original gameplay and purchase-routing assertions remain.

The traced follow-up had no remaining storage-readiness deadlines, purchase deadline
or provider intervals in these fixtures. A 100ms Jest status-reporter timer and a
React scheduler Immediate were transient runner resources; the process exited 0.
They were not suppressed or treated as game defects.
